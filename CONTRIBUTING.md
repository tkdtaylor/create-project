# Contributing to create-project

Thanks for considering a contribution. create-project scaffolds an
agent-driven, test-spec-first workflow — and its own development follows the
same conventions it ships.

## Ground rules

1. **Templates are the product.** Changes under `assets/templates/` reach
   every future scaffolded project; keep examples domain-neutral and
   placeholder-driven (`{{PROJECT_NAME}}`-style).
2. **One concern per PR.** Small, reviewable changes over grab-bags.
3. **DCO sign-off.** Commit with `git commit -s`; by signing off you agree
   your change is licensed under this repo's MIT license.
4. **Keep the skill honest.** `SKILL.md` and the `references/` docs must
   describe what the scaffold actually does — no aspirational claims.

## Security issues

Please do **not** open public issues for vulnerabilities — see
[SECURITY.md](SECURITY.md).
