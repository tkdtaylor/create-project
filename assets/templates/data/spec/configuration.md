## Experiment configs

`experiments/configs/<id>-<name>.yaml` — one file per experiment run. Captures every parameter required to reproduce the run.

### Required keys

| Key | Type | Notes |
|-----|------|-------|
| `id` | string | matches the filename id |
| `name` | string | human-readable name |
| `hypothesis` | string | what this run is testing — required for tracker entry |
| `seed` | int | propagated to numpy / torch / framework |
| `data.dataset` | string | dataset id from [data-model.md](data-model.md) |
| `data.split` | object | rule for train/val/test split (deterministic given `seed`) |
| `model.class` | string | model architecture id |
| `model.hyperparams` | object | full hyperparameter dict |
| `training.<...>` | object | optimizer, schedule, batch size, max epochs |
| `evaluation.metrics` | array | metric keys to compute (must be a subset of `metrics_catalog` below) |
| | | |

### Defaults policy

When a key is omitted, the runtime fills in a default and writes the *resolved* config to `experiments/results/<id>/config.yaml`. The on-disk result is always the full config, not the input — this is what `run-info.json` is compared against for reproducibility audits.

## Path conventions

| Concept | Path | Mutability |
|---------|------|-----------|
| Raw data | `data/raw/<source>/` | immutable |
| Processed data | `data/processed/<name>.<ext>` | regenerated by pipeline |
| External data | `data/external/<source>/` | immutable (third-party snapshots) |
| Experiment configs | `experiments/configs/<id>-<name>.yaml` | versioned in git |
| Experiment results | `experiments/results/<id>/` | written once per run, gitignored except for tracker |
| Model artifacts | `models/<name>/` | gitignored, rebuild from config |
| Notebooks | `notebooks/<NN>-<topic>.ipynb` | versioned |

## Secrets

> Sensitive configuration that lives **outside** the repo. Never commit values; document only the names and where they come from.

| Secret | Source | Used for |
|--------|--------|----------|
| `ANTHROPIC_API_KEY` | `.env` (Docker) or `sbx secret set -g anthropic` (Sandbox) | Claude API access |
| `GIT_TOKEN` | `.env` (Docker) or `sbx secret set -g github` (Sandbox) | Pushing commits from inside Docker / Sandbox |
| | | |

**Rule:** secrets are never pasted into the chat, never logged, and never written into the repo. The `protect-secrets` hook blocks writes to common credential filenames.

## Reproducibility contract

Every run must record enough information to reproduce it bit-exactly (or, where bit-exactness is impossible due to non-determinism, results within documented tolerances). The contract:

- The full resolved config is written to `experiments/results/<id>/config.yaml`.
- `run-info.json` records: `git_sha`, language version, key library versions, hostname, wall time, seed.
- The seed is propagated to *every* source of randomness used: framework RNG, numpy, dataset shuffling, augmentation, dropout where applicable.
- Library versions that affect numerics (BLAS, GPU drivers, framework) are pinned in `requirements.txt` / lock file. Drift in these is a tracked event.

> Update this contract if the project's reproducibility floor changes. **Lowering the floor requires an ADR.**
